# 03.1 Grundselektoren und Attributselektoren

> Modul 03 · Lehrplan 3.2 · Geschätzter Zeitaufwand: 45 Minuten

## Lernziele

- Du wählst Elemente mit Typ-, Klassen-, ID- und Universalselektor aus.
- Du nutzt Attributselektoren (`^=`, `$=`, `*=`, `[type=…]`).

## Voraussetzungen

Modul 02 abgeschlossen

## Ausgangslage

Die Seiten aus Modul 02 haben nur ein kleines Stylesheet mit Typ-Selektoren. Jetzt entsteht eine saubere Selektorstrategie.

## Aufgabe

1. Kopiere den Stand von Modul 02 nach `modul-03` und öffne [`experimente/selektoren-uebung.html`](../portfolio/modul-03/experimente/selektoren-uebung.html). Dort schreibst du alle Selektoren dieses Moduls in den `<style>`-Block.
2. Schreibe Regeln für: (a) alle externen Links (beginnen mit `https`), (b) alle Links auf PDF-Dateien, (c) das E-Mail-Eingabefeld über sein `type`-Attribut. Färbe sie jeweils unterschiedlich.
3. Schreibe einen Selektor für „alle externen Links, die *nicht* auf `example.com` zeigen“.
4. Gib den Artikeln deines Portfolios die Klasse `karte` (HTML ändern) und gestalte sie mit `.karte` (Rand, Innenabstand, heller Hintergrund).
5. Begründe: Warum nimmst du für Styling Klassen und nicht IDs?

## Hinweise

- Typ-Selektoren (`body`, `a`, `h1`) eignen sich für Basis-Styles, Klassen für Bausteine.
- IDs haben hohe Spezifität und sind unflexibel. Sie dienen Ankern (`#inhalt`) und Label-Verknüpfungen.
- `[href$=".pdf" i]` ignoriert Groß- und Kleinschreibung im Attributwert.

---

## Lösung

```css
a[href^="https"]  { color: green; }
a[href$=".pdf"]   { color: crimson; }
input[type="email"] { border: 2px solid navy; }

/* externe Links, aber nicht auf example.com */
a[href^="http"]:not([href*="example.com"]) { color: darkorange; }

.karte {
  margin: 1.5rem 0;
  padding: 0.5rem 1rem;
  border: 1px solid #c5d7ee;
  background: #f5f8fc;
}
```

Fertiger Stand: [`../portfolio/modul-03/css/main.css`](../portfolio/modul-03/css/main.css) (Klasse `.karte`, Attributselektoren).

5. IDs wiegen in der Cascade schwer: `#kopf .logo` schlägt jede Kombination aus Klassen. Dadurch lassen sich ID-Regeln später nur noch mit weiteren IDs oder `!important` überschreiben. Klassen sind wiederverwendbar und leichter überschreibbar.
