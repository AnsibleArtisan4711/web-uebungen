# 05.4 Custom Properties, Design Tokens und Theming

> Modul 05 · Lehrplan 5.5 · Geschätzter Zeitaufwand: 75 Minuten

## Lernziele

- Du definierst Design Tokens als Custom Properties in zwei Ebenen: primitiv und semantisch.
- Du baust ein Theming mit hellem und dunklem Modus über `prefers-color-scheme` und `data-theme`.

## Voraussetzungen

05.3

## Ausgangslage

Farben und Abstände sind im Stylesheet fest verdrahtet. Ein Farbwechsel würde viele Stellen betreffen.

## Aufgabe

1. Definiere in einem neuen Layer `tokens` primitive Tokens (z. B. `--blue-700: #1a3c6e;`) und semantische Tokens (z. B. `--color-primary: var(--blue-700);`). Definiere außerdem Abstands-, Radius- und Schrift-Tokens.
2. Erkläre den Unterschied zwischen primitiven und semantischen Tokens an einem Beispiel. Warum verwenden Komponenten nur semantische Tokens?
3. Ersetze alle festen Farben und Abstände in `main.css` durch `var(--…)`.
4. Definiere die Tokens für Primärfarbe, Hintergrund, Text und einen **Dark Mode**, der über `@media (prefers-color-scheme: dark)` umgeschaltet wird. Ergänze `color-scheme: light dark;`.
5. Teste den Dark Mode: Stelle in den DevTools unter *Rendering* die Emulation von `prefers-color-scheme` um.
6. Ergänze einen **manuellen** Schalter über `data-theme="dark"` auf `html` (der Umschalter selbst folgt in Modul 12). Welches Problem entsteht mit der Systemeinstellung, und wie löst `:not([data-theme="light"])` es?
7. Wofür dient der zweite Wert in `var(--btn-text, #fff)`?

## Hinweise

- Custom Properties beginnen mit `--`, sind vererbbar und zur Laufzeit änderbar (auch per JavaScript).
- `light-dark(#fff, #121212)` ist die Kurzform für Farben, setzt aber `color-scheme` voraus.
- `@property` erlaubt typisierte Variablen mit Standardwert und Animierbarkeit (Modul 15).

## Lösung

1. und 4. Auszug:

```css
@layer reset, tokens, base, components, utilities;

@layer tokens {
  :root {
    color-scheme: light dark;

    /* primitiv */
    --blue-700: #1a3c6e;
    --blue-300: #8fb4ee;
    --white: #ffffff;
    --gray-950: #121212;

    /* semantisch (hell) */
    --color-bg: var(--white);
    --color-primary: var(--blue-700);
  }

  @media (prefers-color-scheme: dark) {
    :root:not([data-theme="light"]) {
      --color-bg: var(--gray-950);
      --color-primary: var(--blue-300);
    }
  }

  :root[data-theme="dark"] {
    --color-bg: var(--gray-950);
    --color-primary: var(--blue-300);
  }
}
```

2. Primitiv: `--blue-700: #1a3c6e` (nur ein Wert, keine Bedeutung). Semantisch: `--color-primary: var(--blue-700)` (Zweck). Ändert man die Marke, tauscht man das primitive Token aus. Im Dark Mode ändert man nur die Zuordnung der semantischen Tokens. Komponenten bleiben unberührt.
5. Chrome/Edge: DevTools → drei Punkte → *More tools* → *Rendering* → *Emulate CSS media feature prefers-color-scheme*.
6. Ohne den Zusatz würde die Systemeinstellung das manuelle „hell“ überstimmen. `:not([data-theme="light"])` nimmt der Systemeinstellung die Wirkung, sobald hell erzwungen wird. Der Umschalter wird in Modul 12 gebaut.
7. Der zweite Wert ist der Fallback, falls die Variable nicht definiert ist.
