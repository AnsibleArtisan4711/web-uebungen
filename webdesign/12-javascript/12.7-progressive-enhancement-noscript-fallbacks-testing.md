# 12.7 Progressive Enhancement, Noscript, Fallbacks, Testing

> Modul 12 · Lehrplan 12.8 · Geschätzter Zeitaufwand: 90 Minuten

## Lernziele

- Du erklärst die drei Ebenen HTML, CSS und JavaScript.
- Du prüfst eine Seite ohne JavaScript.
- Du schreibst Unit-Tests für reine Logik und kennst End-to-End- und Lint-Werkzeuge.

## Voraussetzungen

12.1 bis 12.6

## Ausgangslage

Menü, Filter, Suche und Formular sind fertig. Jetzt prüfst du, ob die Seite auch ohne JavaScript bedienbar ist, und testest die Logik.

## Aufgabe

1. Schalte JavaScript im Browser aus (DevTools: Befehlsmenü „Disable JavaScript“). Prüfe alle Seiten: Ist die Navigation sichtbar? Sind alle Projekte und Blogbeiträge sichtbar? Lässt sich das Formular senden?
2. Welche Teile der Oberfläche erzeugt das Skript (und gibt es sie ohne JavaScript nicht)? Warum ist das richtig so?
3. Wann ist `<noscript>` sinnvoll, wann nicht?
4. Führe die Tests aus: im Ordner `modul-12` `npm test` (oder `node --test`). Welche Funktionen werden getestet, und warum liegt die Logik in `logik.js`?
5. Füge einen Test hinzu, der `passtZuSuche("Grüße", "gruse")` prüft. Läuft er? Falls nicht: was folgt daraus?
6. Fülle [`docs/js-review.md`](../portfolio/modul-12/docs/js-review.md) aus.

## Hinweise

- Feature Detection (`"IntersectionObserver" in window`, `@supports`) statt Browser-Erkennung.
- Inhalte, die ohne JavaScript unerreichbar wären, nie per JavaScript verstecken.
- Tests: [`tests/logik.test.js`](../portfolio/modul-12/tests/logik.test.js).

## Lösung

1. Gemessen/begründet: Die Navigation bleibt sichtbar, denn das Ausblenden greift nur mit der Klasse `html.js`. Filter-Chips und Suchfeld entstehen erst durch JavaScript, daher sind alle drei Projekte und alle Beiträge sichtbar. Das Formular sendet nativ an `danke/index.html`.
2. Menü-Button, Filter-Leiste, Suchfeld, Fehlerliste. Ohne JavaScript wären diese Bedienelemente funktionslos; sie gar nicht erst anzuzeigen ist die ehrliche Lösung. Das ist Progressive Enhancement: Inhalt und Grundfunktion im HTML, JavaScript ergänzt.
3. Sinnvoll für einen Hinweis oder Link, wenn etwas wirklich nicht ohne Skript geht. Nicht sinnvoll als Ersatz für eine Basisfunktion, die auch ohne Skript gehen sollte.
4. Ausgabe (Node {22}): 6 Tests, 6 bestanden, 0 fehlgeschlagen (`tests 6`, `pass 6`, `fail 0`). Die Logik hat keinen DOM-Zugriff und lässt sich deshalb in Node ohne Browser testen.

   Wichtig: `node --test tests/` (mit Ordnerangabe) schlug in Node 22 fehl („Cannot find module …/tests“). Verwende `node --test` ohne Pfad.
5. ```js
test("Umlaute", () => { assert.equal(L.passtZuSuche("Grüße", "gruse"), true); });
```
   `ü` wird per Unicode-Zerlegung zu `u`, das `ß` bleibt jedoch `ß`. Der Test schlägt daher mit `gruse` fehl. Genau dafür sind Tests da: Sie zeigen, dass die Suche `ß` nicht zu `ss` normalisiert.
6. Die Ergebnisse trägst du selbst ein.

   **Nicht getestet:** Firefox/Safari, Screenreader, echte Touch-Geräte. Für End-to-End bietet sich Playwright an, für Stil und Fehler ESLint (nicht Teil dieses Repos).
