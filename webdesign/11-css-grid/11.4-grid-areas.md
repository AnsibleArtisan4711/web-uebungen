# 11.4 Grid Areas

> Modul 11 · Lehrplan 11.5 · Geschätzter Zeitaufwand: 75 Minuten

## Lernziele

- Du definierst Layouts mit `grid-template-areas` und `grid-area`.
- Du baust das klassische Seitenlayout mobil einspaltig.
- Du erklärst, warum die Quelltextreihenfolge die logische Reihenfolge bleiben muss.

## Voraussetzungen

11.3

## Ausgangslage

Das Blog-Layout und das Lebenslauf-Raster im Portfolio nutzen benannte Bereiche. Du baust nun das klassische Seitenlayout selbst.

## Aufgabe

1. Erstelle das klassische Seitenlayout (Header, Navi, Inhalt, Footer) mit `grid-template-areas`, mobil einspaltig. Vorlage zum Vergleich: [`experimente/seitenlayout-areas.html`](../portfolio/modul-11/experimente/seitenlayout-areas.html).
2. Was kennzeichnet ein Punkt `.` in `grid-template-areas`?
3. Warum bleibt die Quelltextreihenfolge (Kopf, Navi, Inhalt, Fuß) wichtig, auch wenn das Layout beliebig umsortieren kann? Nenne zwei WCAG-Kriterien.
4. Untersuche `.lebenslauf-raster` im Portfolio ([`css/main.css`](../portfolio/modul-11/css/main.css)): Warum steht im HTML die Reihenfolge Stationen, Kenntnisse, Ausbildung?
5. Wie ändert sich das Layout bei 600 px und bei 1280 px? Miss die Größen der vier Bereiche.

## Hinweise

- Jede Zeile in `grid-template-areas` ist ein String, alle Zeilen müssen gleich viele Zellen haben.
- Ein Bereichsname muss ein Rechteck bilden.
- `order` und `grid-area` ändern nur die Darstellung, nicht die Tab- und Leseordnung.

---

## Lösung

1. ```css
.seite { display: grid; grid-template-columns: minmax(0, 1fr);
         grid-template-areas: "kopf" "navi" "inhalt" "fuss"; }
@media (min-width: 60em) {
  .seite { grid-template-columns: 16rem minmax(0, 1fr);
           grid-template-areas: "kopf kopf" "navi inhalt" "fuss fuss"; }
}
.kopf { grid-area: kopf; } .navi { grid-area: navi; } .inhalt { grid-area: inhalt; } .fuss { grid-area: fuss; }
```
2. Ein Punkt steht für eine leere, unbenutzte Zelle.
3. Tastatur- und Leseordnung folgen dem Quelltext. Weicht die sichtbare Reihenfolge ab, springt der Fokus scheinbar wild. WCAG 1.3.2 (Sinnvolle Reihenfolge) und 2.4.3 (Fokus-Reihenfolge).
4. Visuell: links Stationen, rechts Kenntnisse, darunter Ausbildung. Diese Reihenfolge entspricht dem Quelltext. Stünde Ausbildung im HTML zwischen den beiden, würden Tastatur und Screenreader sie in einer anderen Reihenfolge durchlaufen, als man sie sieht.
5. Gemessen im Experiment: Bei 600 px vier Bereiche untereinander (je 600 px breit). Bei 1280 px: Kopf 1280 × 46, Navi 256 × 708 links, Inhalt 1024 × 708, Fuß 1280 × 46.
