# 17.5 Utility-CSS und Component Styling

> Modul 17 · Lehrplan 17.6 · Geschätzter Zeitaufwand: 90 Minuten

## Lernziele

- Du nennst Vor- und Nachteile von Utility-CSS.
- Du setzt kleine Layout-Muster (`stack`, `cluster`) ein.
- Du bildest Varianten mit Modifier-Klassen und Custom Properties ab.

## Voraussetzungen

17.3

## Ausgangslage

Du hast Muster ohne Gestaltung: `.stack` und `.cluster`. Dazu soll eine Button-Variante ohne neue Regel auskommen.

## Aufgabe

1. Nenne je zwei Vor- und Nachteile von Utility-CSS (z. B. Tailwind).
2. Lies [`css/src/04-objects.css`](../portfolio/modul-17/css/src/04-objects.css). Wo wird `.stack` im Portfolio eingesetzt, wo `.cluster`? Prüfe in den DevTools die berechneten Werte.
3. Ändere in den DevTools `--stack-gap` am Stack der Styleguide-Seite auf `2rem`. Was passiert mit dem Abstand? Welchen Nachteil nennt der Kommentar im Code (Außenabstände der Kinder)?
4. Baue eine Button-Variante `btn--gefahr` (roter Hintergrund) **ohne** eine neue Farbregel zu schreiben, nur mit der Custom Property `--btn-bg`. Prüfe sie in beiden Farbschemata.
5. Welche Wege zum Component Styling gibt es (BEM, CSS Modules, `@scope`, Shadow DOM, Utilities)? Probiere `@scope` in [`experimente/scope.html`](../portfolio/modul-17/experimente/scope.html).

## Hinweise

- Ein Button liest seine Farben aus `--btn-bg` und `--btn-fg`. Du musst nur diese Variablen setzen.
- Custom Properties werden vererbt: Sie lassen sich an einer Variante oder an einem Container setzen.

## Lösung

1. Vorteile: schnelle Entwicklung (kein Benennen) und konsistente Werte; das CSS wächst kaum, weil dieselben Klassen überall genutzt werden. Nachteile: lange, schwer lesbare Klassenlisten im Markup; es braucht Disziplin, wiederkehrende Gruppen als Komponente zu fassen; Lernkurve für die Klassennamen.
2. `.stack` (Spalte mit Abstand) sitzt am Kontaktformular (`class="formular stack"`), `.cluster` (nebeneinander, bricht um) an der Gruppe der Buttons auf der Startseite. Gemessen: Das Formular hat `display: flex`, `flex-direction: column` und `row-gap: 16px`. Der Cluster hat `display: flex`, `flex-wrap: wrap`, `row-gap: 8px`, `column-gap: 16px`. Die Muster legen nur Abstand und Anordnung fest, nie Farben.
3. Gemessen: Vorher 16 px, nachher 32 px. Eigene `margin`-Werte der Kinder kommen zu `gap` hinzu. Gemessen im Kontaktformular: Die Fehlerliste hat 16 px Außenabstand unten und liegt dadurch 32 px von ihrem Nachbarn entfernt. Der Kommentar im Code warnt davor.
4. ```css
.btn--gefahr { --btn-bg: var(--color-error); }
```
   Gemessen: hell Hintergrund `rgb(176, 0, 32)`, Text `rgb(255, 255, 255)`; dunkel Hintergrund `rgb(255, 138, 149)`, Text `rgb(18, 18, 18)`. Der berechnete Kontrast (WCAG-Formel) beträgt 7,33:1 (hell) und 8,32:1 (dunkel), also über 4,5:1. Hover, Fokus und Übergang gibt es kostenlos, weil sie aus `.btn` kommen. (Beim Test lag die Regel als eigener Stil auf der Seite, nicht in `css/src`.)
5. - **BEM** in einem Stylesheet: Benennung schützt vor Kollisionen.
   - **CSS Modules**: Namen werden beim Bauen eindeutig gemacht (braucht einen Bundler).
   - **`@scope`**: Regeln gelten nur in einem Teil des DOM, auch mit Ausnahme (`to (…)`).
   - **Shadow DOM** (Web Components): vollständige Abschirmung.
   - **Utilities**: Einzweck-Klassen im HTML.

   Gemessen in `scope.html` (Chromium 153): `CSSScopeRule` ist vorhanden; der Absatz in `.demo` ist türkis (`rgb(0, 128, 128)`), der Absatz außerhalb und der in der Ausnahme `.ausnahme` sind schwarz. Entscheidend ist ein im Team vereinbarter Weg.

   **Nicht getestet:** `@scope` in anderen Browsern (Verfügbarkeit nachprüfen, bevor du es produktiv nutzt), Shadow DOM, CSS Modules.

## Erweiterungen

- Baue `.stack` so um, dass Kinder mit eigenem `margin` den Abstand nicht verdoppeln, ohne die Seite zu verändern. Prüfe mit dem Pixelvergleich.
