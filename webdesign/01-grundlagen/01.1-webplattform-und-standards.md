# 01.1 Webplattform und Standards

> Modul 01 · Lehrplan 1.2 · Geschätzter Zeitaufwand: 30 Minuten

## Lernziele

- Du kannst die Bausteine der Webplattform benennen und ihre Aufgaben trennen: HTML = Struktur, CSS = Darstellung, JavaScript = Verhalten.
- Du weißt, welche Organisation welchen Standard pflegt.
- Du kannst mit MDN und webstatus.dev prüfen, ob ein Feature produktiv einsetzbar ist (Baseline).

## Voraussetzungen

Keine. Du brauchst nur einen aktuellen Browser und einen Texteditor.

## Ausgangslage

Dein Portfolio existiert noch nicht. In dieser Übung klärst du das Fundament, auf dem alles aufbaut.

## Aufgabe

1. **Drei Schichten:** Lege die Datei `notizen/01.1-webplattform.md` an. Beschreibe darin in je einem Satz, was HTML, CSS und JavaScript für dein Portfolio übernehmen sollen (z. B. „Lebenslauf-Tabelle“, „Farbe der Überschriften“, „Projektfilter“).
2. **Standardisierer zuordnen:** Ordne diese Technologien der pflegenden Organisation zu: HTML, CSS, JavaScript (ECMAScript), HTTP. Zur Auswahl: WHATWG, W3C (CSS Working Group), Ecma TC39, IETF.
3. **Warum Standards?** Nenne drei Gründe, warum dieselbe Seite in Chrome, Firefox und Safari funktionieren kann.
4. **Baseline prüfen:** Suche auf <https://webstatus.dev> oder in der MDN-Kompatibilitätstabelle ein CSS-Feature deiner Wahl. Notiere: Ist es *Newly available* oder *Widely available*? Würdest du es für den Kern deines Portfolios verwenden?

## Hinweise

- Der HTML-Standard heißt *HTML Living Standard* und hat keine Versionsnummern mehr. „HTML5“ ist ein historischer Begriff.
- *Widely available* bedeutet: läuft seit mindestens 30 Monaten in allen aktuellen Browsern. Neuere Features setzt man als Verbesserung ein (Progressive Enhancement), nicht als Voraussetzung.

---

## Lösung

1. Beispiel:
   ```markdown
   - HTML: Gerüst und Bedeutung der Inhalte (Überschriften, Lebenslauf-Tabelle, Projektliste)
   - CSS: Farben, Schrift, Abstände, Layout, Anpassung an Handy und Desktop
   - JavaScript: Verhalten, z. B. Projektfilter und Menü auf dem Handy
   ```
2. HTML → WHATWG · CSS → W3C (CSS Working Group) · JavaScript → Ecma TC39 · HTTP → IETF.
3. Interoperabilität (gleiches Verhalten in allen Browsern), Sicherheit (definierte Modelle wie die Same-Origin-Policy), Wartbarkeit (alter Code läuft weiter, Abwärtskompatibilität).
4. Individuell. Die Entscheidungsregel lautet: Kernfunktionen nur mit *Widely available*, alles Neuere optional als Verbesserung.
