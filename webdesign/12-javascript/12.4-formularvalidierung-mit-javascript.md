# 12.4 Formularvalidierung mit JavaScript

> Modul 12 · Lehrplan 12.5 · Geschätzter Zeitaufwand: 90 Minuten

## Lernziele

- Du baust auf HTML-Constraints auf und ergänzt JavaScript nur für bessere Meldungen.
- Du fasst Fehler in einer Liste zusammen und setzt den Fokus.
- Du verknüpfst Meldungen per `aria-describedby`.

## Voraussetzungen

12.3, 12.4 und Modul 06

## Ausgangslage

Das Kontaktformular validiert nur mit den nativen Browser-Meldungen.

## Aufgabe

1. Teste [`kontakt/index.html`](../portfolio/modul-12/kontakt/index.html): Klicke ohne Eingabe auf Senden. Was passiert mit ausgeschaltetem JavaScript, was mit eingeschaltetem?
2. Warum setzt `initKontaktFormular` `form.noValidate = true`, und warum ist das ohne JavaScript unschädlich?
3. Welche Elemente erzeugt das Skript pro Feld und für die ganze Seite? Wie verknüpft es sie?
4. Warum wird die Fehlerliste fokussiert (`tabIndex = -1`)?
5. Die Meldungen sollen verschwinden, sobald das Feld wieder gültig ist. Wo geschieht das?
6. Warum ersetzt die JavaScript-Prüfung nie die Prüfung am Server?

## Hinweise

- `checkValidity()` nutzt die HTML-Regeln (`required`, `type`, `minlength`).
- `aria-invalid="true"` markiert ungültige Felder, das CSS färbt sie.
- `setCustomValidity("")` muss den Fehler wieder löschen, sonst bleibt das Feld ungültig.

---

## Lösung

1. Ohne JavaScript zeigt der Browser seine eigenen Meldungen am ersten ungültigen Feld. Mit JavaScript erscheint oben eine Liste (`role="alert"`) „Bitte korrigiere 5 Eingaben“ mit Texten pro Feld. Gemessen: 5 Felder bekommen `aria-invalid="true"`, der Fokus liegt auf der Liste (`.fehlerliste`).
2. `noValidate` schaltet nur die eingebauten Sprechblasen aus, damit die eigenen Meldungen nicht doppelt erscheinen. Es wird erst von JavaScript gesetzt. Läuft es nicht, bleibt die native Prüfung aktiv.
3. Pro Feld ein `p#<id>-fehler.fehlermeldung`, per `aria-describedby` am Feld angehängt (zusätzlich zu vorhandenen Hinweisen). Für die Seite ein `div.fehlerliste`.
4. Nach dem Absenden sieht und hört man sonst nichts vom Fehler. Der Fokus auf der Liste lässt den Screenreader sie vorlesen; `tabIndex = -1` macht ein Nicht-Formularelement fokussierbar, ohne es in die Tab-Reihenfolge aufzunehmen.
5. Im `input`-Handler: Er entfernt Meldung und `aria-invalid` des Feldes, wenn `checkValidity()` wahr ist. Gemessen: Nach Eingabe im Namensfeld sinkt die Zahl der markierten Felder von 5 auf 4.
6. Wer das Formular umgeht (Entwicklerwerkzeuge, direkter Request), sendet beliebige Daten. Der Server muss alles erneut prüfen (Modul 18).

   Gültige Eingaben führen zur Seite `kontakt/danke/index.html` (gemessen).

## Erweiterungen
