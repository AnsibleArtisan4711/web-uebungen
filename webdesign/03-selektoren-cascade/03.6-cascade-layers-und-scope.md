# 03.6 Cascade Layers und Scope

> Modul 03 · Lehrplan 3.7 · Geschätzter Zeitaufwand: 60 Minuten

## Lernziele

- Du ordnest Regeln mit `@layer` unabhängig von der Spezifität.
- Du kennst `@scope` und natives CSS-Nesting und wägst die Browser-Unterstützung ab.

## Voraussetzungen

03.5

## Ausgangslage

Das Stylesheet ist eine lange Liste. Layer bringen Struktur.

## Aufgabe

1. Teile `css/main.css` in vier Layer: `reset`, `base`, `components`, `utilities`. Lege die Reihenfolge mit `@layer reset, base, components, utilities;` am Dateianfang fest.
2. Verschiebe Typ-Selektoren in `base`, Klassen-Bausteine (`.karte`, `.nav`, `.hinweis`) in `components` und Hilfsklassen (`.text-klein`) in `utilities`.
3. Beweise: Eine Regel in `utilities` mit niedriger Spezifität (`.mt-0`) gewinnt gegen eine Regel in `components` mit höherer Spezifität. Teste es.
4. Was passiert mit einer Regel **ohne** Layer? Warum ist das gefährlich, wenn du schrittweise umbaust?
5. Schreibe eine Karte mit nativem **Nesting** (`&:hover`, `& h2`) und eine `@scope`-Regel, die nur Bilder innerhalb von `.karte` rundet. Wie sicher ist `@scope` einsetzbar?

## Hinweise

- Ein später deklarierter Layer gewinnt gegen einen früheren, egal wie spezifisch die Regeln sind. Bei `!important` ist es umgekehrt.
- Ungelayerte Regeln schlagen **alle** Layer. Das ist nützlich, um Bibliotheks-CSS in einen niedrigen Layer zu legen.
- Stand der Nachrecherche: Nesting und `@layer` sind *widely available*, `@scope` ist neu (seit 2026). `@scope` daher nur als Verbesserung einsetzen und gegen die Zielbrowser prüfen.

## Lösung

```css
@layer reset, base, components, utilities;

@layer base       { a { color: #0b4fb3; } }
@layer components { .nav a { color: #1a3c6e; } }      /* (0,1,1) */
@layer utilities  { .text-klein { font-size: .875rem; } }

/* Nesting */
.karte {
  padding: 1rem;
  & h2 { font-size: 1.25rem; }
  &:hover { box-shadow: 0 2px 8px #0003; }
}

/* Scope */
@scope (.karte) {
  img { border-radius: 8px; }
}
```

Fertiger Stand mit Layern: [`../portfolio/modul-03/css/main.css`](../portfolio/modul-03/css/main.css) und die Regeln in [`../portfolio/modul-03/docs/css-konventionen.md`](../portfolio/modul-03/docs/css-konventionen.md).

3. Eine `utilities`-Regel mit (0,1,0) gewinnt gegen eine `components`-Regel mit (0,3,1), weil der Layer früher entscheidet als die Spezifität.
4. Sie gewinnt gegen alle Layer. Beim schrittweisen Umbau überschreibt übersehener ungelayerter Code deshalb unbemerkt die neue Struktur. Deshalb liegen alle Regeln in einem Layer.
5. Laut Nachrecherche im Lehrplan ist `@scope` seit März 2026 *newly available*. Es gehört deshalb nicht in den Kern, sondern höchstens als Verbesserung. Prüfe den aktuellen Stand bei MDN oder webstatus.dev.
